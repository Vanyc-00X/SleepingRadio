# Техническое задание: «Сонный радиоприёмник»

## 1. Общее описание

* **Название (рабочее):** Сонный радиоприёмник
* **Платформа:** мобильное приложение (iOS + Android), **приоритет — Android**
* **Тип продукта:** офлайн/онлайн аудиоплеер для засыпания и фонового прослушивания
* **Суть:** приложение превращает книги, новости и интернет-материалы в спокойную голосовую «станцию»: читает текст приятным голосом, при необходимости коротко комментирует и может собирать из этого подкастоподобные выпуски. Пользователь задаёт таймер — через $N$ минут звук плавно затухает и воспроизведение останавливается.
* **Главная ценность:** *«Лёг вечером $\rightarrow$ выбрал источник $\rightarrow$ слушает спокойный голос $\rightarrow$ заснул без яркого экрана»*.

---

## 2. Цели продукта

1. Дать удобное ночное прослушивание книг (`.fb2`, `.epub` и др.).
2. Озвучивать свежие новости с мягким комментарием ИИ.
3. По ссылке читать и комментировать статью или пост.
4. Генерировать короткие «подкасты» из выбранных материалов.
5. Управлять сессией через таймер сна и минималистичный UI.

> **Не цель MVP:** соцсеть, маркетплейс подкастов, полноценный аудиокнижный магазин, стриминг музыки.

---

## 3. Целевая аудитория

* Люди, которые засыпают под голос или подкасты.
* Читатели, которым удобнее слушать, чем смотреть в экран.
* Студенты и работающие люди, желающие «дойти» новости/статьи аудиально по дороге или перед сном.

**Контекст использования:** ночь, полумрак, одна рука, возможно с закрытыми глазами после старта.

---

## 4. Пользовательские сценарии

### Сценарий A — Книга на ночь
1. Пользователь импортирует файл книги.
2. Выбирает главу / позицию.
3. Ставит таймер (например, 30 минут).
4. Запускает чтение.
5. Через 30 минут приложение плавно затихает и останавливается, позиция сохраняется.

### Сценарий B — Новости
1. Пользователь открывает раздел «Новости».
2. Выбирает темы / источники (или «для вас»).
3. ИИ собирает краткую сводку, озвучивает и добавляет спокойный комментарий.
4. Можно листать «следующий выпуск» жестом или кнопкой.

### Сценарий C — Ссылка
1. Пользователь вставляет URL статьи/поста (или шарит ссылку из браузера).
2. Приложение извлекает текст.
3. Озвучивает содержание + короткий комментарий (тон: нейтральный, без кликбейта).
4. Опционально сохраняет как «выпуск».

### Сценарий D — Сгенерированный подкаст
1. Пользователь выбирает 1–5 материалов (новости / ссылки / глава книги).
2. Нажимает «Собрать выпуск».
3. ИИ формирует структуру: *интро $\rightarrow$ блоки $\rightarrow$ мягкое аутро*.
4. Выпуск озвучивается и становится доступен в библиотеке.

## 5. Функциональные требования

### 5.1. Онбординг и профиль
* **Первый запуск:** короткое объяснение (максимум 3 экрана).
* **Выбор предпочтений:** темы новостей, длина комментария, уровень «разговорности».
* **Выбор голоса TTS:** минимум 2 голоса в MVP.
* **Профиль:** локальный профиль без обязательной регистрации в MVP *(аккаунт для синхронизации библиотеки — опционально позже)*.

### 5.2. Таймер сна
* **Предустановки:** 15 / 30 / 45 / 60 / 90 минут + ввод своего значения.
* **Плавное затухание:** за последние 30–60 секунд.
* **После остановки:** автосохранение позиции книги/выпуска.
* **Управление:** возможность продлить таймер на +15 минут с экрана *Now Playing* или *Lock Screen*.
* **Специальный режим:** «играть до конца главы/выпуска» (без фиксированного времени).

### 5.3. Книги
* **Форматы (MVP):**
  * *Обязательные:* `.fb2`, `.epub`
  * *Желательные:* `.txt`, `.pdf` (только текстовый слой; сканы и OCR — post-MVP)
* **Возможности:**
  * Импорт из файлового менеджера / системного меню «Поделиться».
  * Парсинг оглавления (где доступно).
  * Удобная навигация по главам.
  * Сохранение прогресса (книга, глава, % или символьная позиция).
  * Регулировка скорости чтения: $0.8\times \text{–} 1.5\times$.
  * Режим «Только чтение» (без комментариев ИИ).
  * *Опционально:* краткое резюме главы перед чтением (переключатель/toggle).

### 5.4. Новости
* Раздел «Новости» с лентой тематических выпусков.
* **Источники:** настраиваемый список RSS/API (конкретный провайдер выбирается на этапе реализации).
* **ИИ-пайплайн для каждого блока:**
  1. Сбор/суммаризация 3–10 материалов;
  2. Нейтральный пересказ;
  3. Короткий комментарий (1–3 предложения);
  4. Озвучка.
* **Фильтры:** Политика / Технологии / Наука / Культура / Спорт / Local *(опционально)*.
* **Явный дисклеймер:** *«Сводка может содержать неточности; это не официальный СМИ-продукт»*.
* Кнопка «Без комментариев» / «Только факты».

### 5.5. Интернет-ресурс по URL
* Поле ввода URL + share-target из системы.
* Извлечение основного текста (reader-mode подобный парсинг).
* Если текст не извлечён — понятная ошибка и fallback (*«Не удалось прочитать страницу»*).
* **Режимы:**
  * «Прочитать»
  * «Прочитать + прокомментировать»
  * «Краткий пересказ + комментарий»
* Сохранение материала в библиотеку.

### 5.6. Генерация подкастов
* **Конструктор выпуска:** *интро $\rightarrow$ 1–5 сегментов $\rightarrow$ аутро / «спокойной ночи»*.
* **Целевая длительность:** ~5 / 10 / 20 минут.
* **Тон:** спокойный, вечерний, без резких шумов и громких перепадов.
* Повторное прослушивание из библиотеки.
* *(Post-MVP)* фоновый hum/ambient bed под голосом (очень тихо).

### 5.7. Плеер
* Play / Pause / Seek ($\pm 15$ секунд).
* Next / Prev сегмент (для новостей и подкастов).
* Фоновая работа (Background Audio Service).
* Управление с экранов блокировки (Lock Screen) и с гарнитуры/наушников.
* **Отображение:** название, источник, оставшееся время таймера.
* Минимальная яркость UI / тёмная тема по умолчанию.
* **«Ночной режим»:** минимум анимаций, крупный Play/Pause.

### 5.8. Библиотека
* **Вкладки:** Книги / Выпуски / Ссылки / Избранное.
* История прослушиваний.
* Удаление и переименование записей.
* Офлайн-доступ к уже сгенерированному аудио (если хранится локально).

### 5.9. Настройки голоса и ИИ
* Выбор голоса TTS.
* Настройка скорости и высоты тона (если поддерживает движок).
* Длина комментария: *коротко / средне / выключено*.
* Язык: русский (MVP), другие — в следующих версиях.
* Переключатель: облачный TTS/LLM vs локальный (если позволяет устройство).

### 5.10. Безопасность и этика контента
* Не озвучивать paywall/private контент без доступа.
* Не претендовать на дословную точность новостей при суммаризации.
* Возможность пожаловаться на плохой комментарий или галлюцинацию ИИ.
* Контент 18+ / жестокий — мягкое предупреждение или автопропуск в ночном режиме.

## 6. Нефункциональные требования

| Параметр | Требование |
| :--- | :--- |
| **Старт воспроизведения** | $\le 2$ сек (для готового аудио) |
| **Первая озвучка короткого текста** | $\le 30\text{--}60$ сек на среднем устройстве/сети (до ~5 тыс. знаков) |
| **Фоновая работа** | Стабильно при блокировке экрана |
| **Размер офлайн-кэша** | Настройка лимита (например, 1–5 ГБ) |
| **Батарея** | Экономный расход: не держать экран включённым, щадящий polling |
| **Доступность (Accessibility)** | Крупные кнопки, базовая поддержка TalkBack / VoiceOver |
| **Офлайн-режим** | Книги и сгенерированные аудио доступны без сети; новости/URL/генерация требуют интернет (или локальную модель) |

## 7. UX / Экраны (MVP)

1. **Home:** блок «Продолжить», быстрые режимы (*Книга / Новости / Ссылка / Подкаст*).
2. **Библиотека**
3. **Импорт книги**
4. **Новости:** выбор тем + кнопка *«Сформировать выпуск»*.
5. **URL Reader:** поле ввода ссылки + выбор режима чтения.
6. **Конструктор подкаста**
7. **Now Playing:** таймер, скорость, переключатель комментариев (*On / Off*).
8. **Настройки**

### UI-принципы
* Тёмная палитра, низкий контрастный «шум».
* Один главный CTA-элемент на экран.
* Всё критически важное доступно с экрана *Now Playing* в 1–2 тапа.

## 8. Логическая архитектура

```text
[UI App]
   ↓
[Session Manager: timer, playback queue, progress]
   ↓
[Content Pipeline]
   ├─ Book Parser (fb2/epub/txt)
   ├─ Web Extractor (URL → text)
   ├─ News Aggregator (RSS/API)
   └─ Podcast Composer (LLM)
   ↓
[AI Layer]
   ├─ Summarizer / Commenter (LLM)
   └─ TTS Engine
   ↓
[Audio Cache + Local DB]
   ↓
[Player Service (background)]
```

### 8.1. AI-поведение (обязательные правила промптов)
* **Тон:** спокойный, тёплый, без сенсаций и резких эмоций.
* **Комментарий:** не мнение «в лоб», а скорее контекст, мягкое пояснение или вопрос для размышления.
* **Для новостей:** сначала подавать факты, затем комментарий (явно их разделять).
* **Для книг:** избегать спойлеров (по умолчанию комментарии для книг выключены).
* **Длина:** строго ограничена выбранной настройкой.

---

## 9. Минимальная модель данных

* **UserSettings:** голос, скорость, темы, таймер по умолчанию, лимит кэша.
* **Book:** метаданные, путь к файлу, оглавление, прогресс (`progress`).
* **SourceMaterial:** URL / новостной элемент / сырой текст, извлечённый текст, статус обработки.
* **Episode:** тип (`book_chapter` / `news` / `url` / `podcast`), скрипт, `audioPath`, длительность.
* **PlaybackSession:** `currentEpisode`, позиция, `timerEndsAt`, состояние плеера.
* **ListenHistory:** история сессий и прослушиваний.

## 10. Технические ограничения и выборы

### Рекомендуемый стек
* **Клиент:** Flutter или React Native.
* **Локальная БД:** Drift / SQLite / Hive.
* **Фоновое аудио:** платформенные audio service плагины (`audio_service` / `just_audio`).
* **Парсинг книг:** библиотеки под выбранный стек для парсинга `.epub` и `.fb2`.
* **URL extract:** server-side reader или локальный extractor + fallback.
* **LLM:** облачные API (быстрее для MVP) с заделом под Ollama / локальные модели.
* **TTS:** облачный neural TTS (для максимального качества и спокойного голоса); локальный TTS как fallback.

### Политика приватности
* Книги пользователя по умолчанию **не загружаются** в облако целиком (только чанками при необходимости облачного TTS).
* Для облачного TTS/LLM отправляются только необходимые минимальные фрагменты текста.
* Прозрачный экран для пользователя: *«Что уходит в сеть»*.

## 12. Критерии приёмки MVP

1. Пользователь может импортировать `.epub` / `.fb2` и слушать книгу в фоне с включённым таймером.
2. По истечении таймера воспроизведение останавливается с плавным fade-out, а прогресс прослушивания сохраняется.
3. Статья по URL корректно извлекается и озвучивается; режим с комментарием добавляет отдельный короткий блок после текста.
4. Раздел новостей успешно формирует выпуск «сводка + комментарий» и воспроизводит его.
5. Приложение стабильно работает в фоне без сбоев при блокировке экрана в течение $\ge 30$ минут.
6. Доступны рабочие настройки выбора голоса, скорости и длины комментария.
7. Все ошибки парсинга или сети выводятся понятным пользователю языком.

## 13. Риски и митигация

| Риск | Митигация |
| :--- | :--- |
| **Качество TTS не подходить для сна** | Тестирование 2–3 разных TTS-движков, A/B-тесты голосов |
| **Галлюцинации ИИ в новостях** | Жёсткие рамки в системном промпте: факты отдельно, явный дисклеймер |
| **Сайты не парсятся (защита/структура)** | Использование fallback-провайдеров + понятное сообщение об ошибке |
| **Высокая стоимость облачных API** | Чанкование текста, агрессивное кэширование аудио, лимиты на генерацию |
| **Авторские права на контент** | Работа только с user-imported файлами и публичными RSS-лентами; отсутствие встроенной пиратской библиотеки |

---

## 14. Метрики успеха (после запуска)

* % сессий с запущенным таймером сна;
* Медианная длительность одной сессии;
* % успешно распарсенных URL-ссылок;
* Доля дослушанных до конца новостных выпусков;
* Retention D1 / D7;
* Количество повторных открытий карточки «Продолжить книгу».

## 15. Продукт в одну фразу

> **«Сонный радиоприёмник»** — ночное аудиоприложение, которое спокойным голосом читает ваши книги, коротко разбирает новости и ссылки и умеет собирать из этого мягкие подкасты с таймером засыпания.
